# 一次实践历练：从零搭建 AI Agent 的夏天

**实践单位**：信雅达科技股份有限公司 AI 事业部  
**实践时间**：2026年7月—8月  
**实践人**：骆嘉铭（华南理工大学 铭诚书院 智能制造专业）

---

高考结束后，我终于有机会满足自己对人工智能一直以来的兴趣。我进入了信雅达科技股份有限公司 AI 事业部实习。彼时我已掌握一定程度的 Python 编程，也通过线上课程对 AI 的基本概念有了初步了解。部门负责人给我定了一个明确的目标：这个暑假，从零开始，独立搭建一个 AI Agent。这就是 Go购跨平台购物比价助手的起点。

## 学习：看视频、啃教材、写代码

刚上手的时候，我对 AI Agent 的理解几乎是空白。导师没有给我安排日常杂活，而是让我先把基础打牢。于是整个七月的节奏就是：上午看视频，下午啃教材，晚上写代码。

视频看的清华大学《跟我学 AI》系列讲座。看视频不难，难的是看完之后——我需要交学习报告，每讲一份，拆核心概念、画算法流程、写自己的理解。一开始写得很吃力，一张图反复暂停、一句术语反复查，花了不少时间。好处是，这种硬啃的方式让知识沉得下来——学到 Transformer 那讲的时候，脑中关于"注意力机制"的画面突然清晰了，前面几周的积累一下子通了。

教材是导师推荐的，chemark 写的《深入理解 AI Agent：设计原理与工程实践》。全书十章，从"Agent = LLM + 上下文 + 工具"这个公式讲起。读到这个公式的时候，我终于明白为什么 Agent 不是单纯的"一个聪明的模型"——它需要上下文（眼睛）、需要工具（手脚）、需要一个统合这些东西的架构师思维。书里有 92 个配套实验，我跟着一个个跑，从最基础的 ReAct 循环搭起，后来扩展到了 Harness 工程——就是把模型的输出管住，不该说的不让他说，该重试的重试，该降级的降级。这些细节后来在 Go购 里全都用上了。阅读过程中我也会定期向导师汇报进度，把跑通了的实验结果和遇到的问题整理成简报发给他。

跑完书上大半实验之后，我开始动手了：做一个能同时在淘宝、京东、拼多多、唯品会搜商品的比价工具。

## 从跑不通接口到 v1.0

Go购 前后折腾了几十个版本。最早的版本只调了淘宝联盟的 API，一天只能搜几十个词，搜出来的结果还不是全量——联盟 API 只返回设了佣金的商品，像石头岛、始祖鸟这些大牌根本搜不出来。后来加上了浏览器爬虫通道，单独开一个 Edge 进程模拟正常用户在网页上搜，总算把非佣金商品也补上了。

搜索之外，做了一些市面上少见的设计。

四平台对比。同一个关键词，淘宝、京东、拼多多、唯品会的价格排成一列，组内最低的标绿，店铺评分低于 3.0 的标红。价格太离谱的——低于平均价六成以上的——会弹一条提醒："价差过大，谨防二手或仿品。"

陪你出发。这是后来才加的功能。用户说"想买个游戏本"，系统不急着扔链接，先问预算、用途、有没有不想要的品牌，一轮轮把需要的东西问清楚。这个功能受教材里"上下文工程"的启发——Agent 看到的东西越多，它问的问题就越准。

购物漫游。不知道买什么的时候，系统根据历史搜索和品类偏好扔一串推荐卡片，左右翻着看。不喜欢就点"不感兴趣"，下次自动绕开。漫游玩的是随机发现的感觉，算法上做了几层控制——画像品类为主、类似商品为辅、偶尔混几个新品类、再加上销量热门兜底——不让他连续推三页同一种东西。

好价卡。比价完了点"生成好价卡"，把需求确认、价格对比、店铺信誉、历史走势、低价警示、盯价纪律六项拼成一张卡片。底部还有"三派怎么看"——性价比派说便宜但店铺分低，品质派说京东自营虽然贵一点但售后靠谱，性能派说参数都一样看售后就行。三种角度列在一起比一句"建议买京东"更有参考价值。这张卡可以保存图片、复制文字，我妈在手机上搜洗衣液的时候说了句"这个好，一眼就看懂了"。

店铺评分。DSR、服务分、物流分、好评率、店铺等级，五维打一个综合分。好评率低于 90% 的开降，评分不到 3.0 的直接不让 AI 推荐。新店——当年开的、去年开的——会自动压分，不算一刀切但足够拦住不靠谱的。

盯价和推送。用户设一个心理价位，后台每六小时扫一遍价格，跌破了就通过企业微信发消息。不用守在电脑前刷。

社交媒体参考。对比页往下翻能看到 B站、小红书、贴吧上关于这个商品的相关讨论，每条内容做了简单的情感判断和可信度打分。汇总成一句大实话——"15 位博主推荐，但有 3 个提到续航不满"——比空洞的好评率有用。

后台还有一些不面向用户的东西：每天晚上自动跑采集任务，三十个种子关键词配自动扩展，现在商品库里攒了一万多件商品。费用统计面板精确到每次 DeepSeek API 调用的花销——整个暑假下来不到五十块钱。评估面板追踪"建议采纳率"，看 AI 给的建议有多少次真的推动了用户点击比价按钮或设置了盯价。这些数字本身没什么，但它们让我知道这个产品不是在自娱自乐。

## 收获

技术层面确实攒了不少。FastAPI 搭服务、SQLite 管数据、DrissionPage 控制浏览器抓淘宝宝贝、DeepSeek 做意图解析和 AI 建议、PWA 让手机能当 App 用、企业微信做推送通知——单拎出来任何一个都不算多难，但它们在一个暑假里全部串成了一条生产线，这是在学校课堂上学不到的。

但真让我觉得这个夏天没有白费的，是另外几件事。

第一件事和 AI 协作有关。整个暑假的协作模式靠三个角色同时运转：我拍板方向、WorkBuddy 审核方案、coding agent 执行代码。最开始觉得编程水平是关键，很快就发现搞错了——想法有没有捋清楚才重要。你连自己想让代码干什么都说不明白，给再强的 AI 也跑不好。反过来，等需求拆解清楚了、边界条件考虑到了，剩下的事交给 coding agent 只是时间和试错次数的问题。AI 未必取代工程师，但一定会惩罚想不清楚的人。

第二件事是踩坑。Go购 的版本迭代里有一小半是在修 bug：京东详情页被验证码拦死，淘宝店铺页一碰就清空登录态，采集引擎跑一半 Edge 残留进程锁了端口。这些坑书上不会写，碰上了才知道疼。但记住第一个坑之后，第二个来的时候就没那么慌了。第三个来的时候已经知道排查要先看日志、再看端口、再看进程、再看代码。踩出来的顺序感，记一辈子。

第三件事是数据源。淘宝联盟的 API 只返回有佣金的商品；京东联盟没个人搜索接口，只能靠京粉榜单；唯品会折淘客接口报错，最后绕道浏览器爬取；拼多多 H5 页面把商品数据藏在页面 JSON 里，得在几百 KB 的 HTML 里逐层解析。把四个渠道全部打通是一个有些折磨但足够有意思的过程。做完之后有一个感觉：这个世界上的数据确实就在那里，只是没有谁会主动把它送到你手上。

## 总结

这次实习的核心任务是从零搭建 Go购，干了两个多月，从需求分析做到 v1.0 上线。技术层面的东西——FastAPI、SQLite、DrissionPage、DeepSeek 集成、PWA——都在实际做东西的过程中学到的，和看书学不一样。更重要的是建立了一些习惯：遇到问题先拆、拆完再动手；一个方案不行马上换第二个，不死磕；每天记录当天的进度和卡点，回头看能发现很多自己当时没注意的问题。导师在整个过程中给了很多方向上的建议，在这里一并感谢。

写这份报告的时候，Go购 的 1.0 版本刚上线，弹窗问题也在这两天修完。Go购 算是第一个 Agent 的收官，第二个 Agent 的方向已经有了雏形——金融投资分析。初步的想法是搭一个围绕价值投资的分析工具，融合多因子选股、估值建模（PE/PB/DCF）、财报关键指标提取，再加一层舆情情绪因子，从技术面、基本面、情绪面三个维度交叉验证。和 Go购 不一样的地方在于，这个项目天然适合多 Agent 协作——不同的分析师各自独立出结论、交叉辩论、最后汇总——Go购 里积累的 Harness 工程经验（多通道数据、状态管理、定时推送、评估闭环）可以直接复用到底层。进入华南理工大学后，我会利用课余时间继续推进这个项目，在智能制造专业的学习之外，把搭建有思考能力的 Agent 作为长期方向。
