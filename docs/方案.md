# 全网购物助手 Agent —— 项目方案 v2.0

> 作者：骆永钢（华南理工智能制造大一）｜日期：2026-08-06
> 状态：阶段 0（环境准备）

## 一、项目定位

个人自用为主的**全网购物比价助手**（不下单版），目标用户：自己 → 家人同学。
输入商品名 → 多平台比价 + 博主推荐参考 + 国补/优惠提醒 + 降价监控。

## 二、核心痛点（实测"慢慢买"发现）

1. **价格过时**：数据库快照非实时 → 方案：实时查询
2. **优惠券过期**：展示时有效、点开已结束 → 方案：实时校验
3. **SKU 混淆**：搜"耀世16 Ultra 5080"返回 5060/5070 价格 → 方案：SKU 级归一化匹配

## 三、技术方案（v2.0 更新）

### 数据源（重大调整）
- ✅ **大淘客聚合 API**（淘宝+京东+拼多多+抖音，统一接口）——MVP 首选
- ⚠️ 多多进宝（拼多多联盟）——备选/补充（注意：联盟 API 只返回有佣金商品，覆盖率 60-80%）
- ❌ **放弃爬虫**——2025 新《反不正当竞争法》+ 平台反爬升级，法律/技术风险过高

### 数据存储
- **SQLite**（零配置、Python 自带、单文件）
- **从阶段 1 起每次搜索都存价格**——价格历史曲线需要时间积累

### 产品形态
- Python 后端（FastAPI）+ 网页（手机浏览器/PWA）
- 推送：MVP 用 Server酱（5条/天够测试）→ 阶段 4 切换**企业微信应用消息**（免费、额度高、家人扫码即用）
- 不做原生 App（审核风险 + 开发成本）

### 用户画像（2026-08-06 确认）
- 品类优先级：**服饰第一、食品第二、日用百货第三**，电脑数码作为测试品类（有真实购买经验）
- 使用场景：**买前查价为主**，盯价为辅
- 使用频率：**每天多次**（需缓存层，同商品 24h 内重复查询不重复调 API）
- 界面：**网页版响应式**（本人电脑 + 家人手机），大字少按钮
- 盯价偏好：**短期窗口**（1-2 周），非长期等待型
- 输入方式：**模糊描述为主**（家人）："想买条裙子，款式类似某件" → 意图解析；本人可输品牌型号
- 隐私：数据存自己的服务器可接受，起步存本地 SQLite
- 预算：无上限（功能优先）
- 验收：实际成交价 vs 助手查价对比
- 服饰比价注意：款号/货号是匹配锚点；"同款≠同质"，只标价格不背书质量

## 四、Agent 架构设计

- **核心公式**：Agent = LLM + 上下文 + 工具
- **混合模式**：强约束环节（参数校验）用工作流，模糊意图（"想买个性价比高的本子"）用自主 Agent
- **三维度**：感知（搜索工具）→ 行动（API 调用）→ 策略（比价编排）
- **预算兜底**：MAX_STEPS = 20
- **循环检测四级升级**：注入打破提示 → 回退检查点 → 降级返回部分结果
- **安全围栏**：只读不写（不下单）、工具评级 + 频率限流
- **人工干预**：优雅移交（带答案来问问题）+ 打扰预算（一次会话最多打断 2-3 次）
