## 三、逐条回应甲方质疑

**Q7"约束上线当天被 force 越过？"——不成立。**
集中度硬约束（589ea3c）16:07 才上线——华电买入在它上线前 41 分钟。买入时**不存在**"buy 拒绝"机制，force 参数当时也不存在。不是"越过约束"，是"约束还不存在"。

**Q9"86.4 分不达标为什么还买？"——当时达标。**
86.4 分不达标是**16:07 门槛换算后**的结论（80/120=67% → 96/120=80%）。买入时刻门槛是 80，86.4 > 80 = 达标。事件流原文：`reason: "投完现金决策（2026-08-17——86.4达标+公用高分+B3时机在场——行业面v1上线后首达新仓）"`——记录显示决策依据就是当时规则下的达标。

**Q5"买之前跑过十年回测吗？"——没跑，认。**
买入依据是"打分 86.4 + B3 时机 + 行业面高分"，**没有跑华电 2016-2026 十年回测**（今晚四大师验证才补：华电十年 -0.1%、回撤 73%）。当时流程里没有"历史数据前置检查"环节——这是真缺口，8/18 补进 eval_buy。

## 四、系统性缺陷（比单笔交易更重要的发现）

1. **规则版本未与决策绑定**：决策时点用哪版规则无记录——事后审计只能靠 git 时间戳反推。**修复：eval_buy 输出带"规则版本号"**（打分函数版本+门槛值+接线状态），存进事件流。
2. **审核报告在买入后 22 分钟才发布**：e8039fe（15:48）点名华电 37% 超限——但买入（15:26）在先。**审核与交易并行进行，审核结论来不及阻止交易**。这是流程设计问题：高风险动作（新开仓）应在审核报告发布后执行。
3. **"投完现金决策"路径绕过强制入口的隐患**：买入走了"投完现金"路径（用户拍板），eval_buy 入口 14:28 已存在但该路径未强制调用。**修复：所有买入（含投完现金）必须走 eval_buy——已在 P1 硬约束中，需验证接线。**
