# 爸妈投资书数字化方法论（2026-08-14）

> 目标：142 张 4合1 PPT 扫描图 → Markdown 文字稿 → YAML 策略规则
> 约束：智谱注册不了（GLM-4V 不可用）、半夜 token 被消耗（要零 token 方案）、142 张量大

## 一、核心原则

1. **零 token**——全程本地，不调云端 API（防 token 消耗）
2. **精度优先**——投资策略数字错一个就反了（"<15"读成">15"），宁可慢不可错
3. **分类型处理**——文字/表格/曲线图各有最佳工具，不一刀切
4. **人兜底关键环节**——切图对不对、曲线图语义，人看一眼比工具猜准

## 二、工具链（每步用什么 + 为什么）

| 步骤 | 工具 | 选型理由 |
|------|------|---------|
| ① 切图 | Pi 切图脚本 v2（OpenCV 边界检测+倾斜矫正+2×2 切分+预览） | 已就绪，自动拆 4合1 |
| ② 文字+表格提取 | **textsnap**（`pip install textsnap`，PaddleOCR-VL-1.5 量化版，CPU 跑，离线） | 一行装、零 token、输出 Markdown 保留表格结构、版面语义理解（非机械扫描） |
| ③ 曲线图语义 | **人工描述**（你或我看图描述"画的是X，标注写了Y"） | 量少（~14 张），工具读不准手绘示意图，人看最准 |
| ④ 合并+提炼 | 小布（WorkBuddy）| 提炼成 YAML 策略规则，标注页码，标模糊项 |

**备选工具**（textsnap 出问题时）：
- Umi-OCR（github.com/hiroi-sora/Umi-OCR，图形界面，PaddleOCR 引擎，免安装版）
- PaddleOCR 直接调（github.com/PaddlePaddle/PaddleOCR，69.9k 星，国产 OCR 第一梯队）
- DeepSeek-OCR-2（同家 OCR 模型，91% 准确率，但需 GPU+环境配置，较重）

## 三、执行流程（6 步）

### 步骤 1：Pi 切图（~5 分钟）
```
Pi 跑：python 切图脚本.py "C:\Users\luoji\Desktop\观复\吴老师的书\" --preview
```
- 输出：`吴老师的书/切图/page_0001.jpg` ~ `page_0560.jpg`（约 560 张单页）
- 同时生成预览图（每张原图一行 4 缩略图）

### 步骤 2：人看预览确认（~2 分钟）
- 扫一眼预览图：切对了？没切歪？没漏页？
- **这关不能省**——切错后面全错
- 发现切错的：标记原图，Pi 单独重切

### 步骤 3：装 textsnap（~3 分钟）
```
pip install textsnap -i https://pypi.tuna.tsinghua.edu.cn/simple
```
- 首次运行下载 ~890MB 模型（一次性，之后离线）
- 装在 Pi 的 Python 环境（C:\Users\luoji\.workbuddy\binaries\python\versions\3.13.12）

### 步骤 4：批量 OCR（~30-60 分钟，CPU 跑零 token）
```bash
cd "C:\Users\luoji\Desktop\观复\吴老师的书\切图"
for %f in (*.jpg) do textsnap "%f"
```
- 每张图输出同名 .txt（Markdown 格式，表格/标题结构保留）
- 文件名带页码（page_0001.txt = 第 1 页）

### 步骤 5：曲线图页人工描述（~20 分钟）
- 从 560 张里挑出曲线图页（约 14 张原图 → ~56 单页）
- 你或我看图描述：画的是什么（K线/走势/示意图）+ 标注文字 + 走势
- 单独存 `曲线图描述.md`

### 步骤 6：小布合并+提炼（~30 分钟）
- 合并所有 .txt + 曲线图描述 → `docs/爸妈投资理念.md`（按页码排序）
- 提炼成 YAML 策略规则：

```yaml
# 示例输出格式
买入规则:
  - id: buy_001
    来源: 第12页
    条件: 市盈率 < 15 且 连续3年盈利
    原文: "PE低于15倍，且公司连续三年盈利，可考虑买入"

卖出规则:
  - id: sell_001
    来源: 第28页
    条件: 市盈率 > 30 或 止损-10%
    原文: "PE超过30倍或亏损10%应卖出"

仓位规则:
  - id: pos_001
    来源: 第45页
    规则: 单只个股不超过总仓位20%
    原文: "任何一只股票不超过总资金的20%"

模糊待澄清:
  - 来源: 第33页
    原文: "适时调整仓位"  # "适时"没给标准
    问题: 什么条件触发调整？
```

- 最终输出：`docs/观复策略库_父母样例.md`（Pi 策略引擎填校准槽位）

## 四、质量控制（每步验收标准）

| 步骤 | 验收标准 | 不过怎么办 |
|------|---------|-----------|
| 切图 | 预览图 4 页顺序正确+无歪斜 | Pi 调参重切 |
| OCR | 文字完整率 >95%、网址零遗漏、数字标[存疑] | 换 Umi-OCR 重跑该页 |
| 曲线图 | 标注文字全提取+走势描述准确 | 重拍该页（更清晰） |
| YAML | 每条规则有来源页码+父母能看懂 | 回传父母校对 |

## 五、异常处理

| 情况 | 处理 |
|------|------|
| textsnap 装不上 | 换 Umi-OCR 免安装版（下 zip 解压即用） |
| 某页 OCR 看不清 | 标[模糊：需重拍]，不猜——重拍该页补 |
| 表格识别错位 | 拍照发小布，人工重排成 Markdown 表格 |
| 曲线图太多人工扛不住 | 上 ChartOcr（github.com/analytistic/ChartOcr）试自动识别 |
| 切图脚本检测不到边界 | 用降级兜底（按全图 2×2 切+警告） |

## 七、不做什么（排雷）

- ❌ 不用智谱 GLM-4V（注册不了）
- ❌ 不用云端 OCR API（烧 token）
- ❌ 不用纯人工录入（142 张太多）
- ❌ 不等父母策略样例才开工（策略引擎按通用规则设计，样例到位填校准槽位——方案已定）
