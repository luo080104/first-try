## 一、总体架构（五层）

```
┌─────────────────────────────────────────────────┐
│ ⑦ 推送层：企业微信（早8:30晨报/盘中信号/晚报/周报/风险提醒） │
├─────────────────────────────────────────────────┤
│ ⑥ 确认层：半自动（信号带理由+讲解+多视角摘要 → 你确认 → 恒泰手动） │
├─────────────────────────────────────────────────┤
│ ⑤ 信号层：多视角评审（四大师/Bull-Bear/评审团）→ 强制结论格式    │
│     + 机械自查 gate（13项）→ 可问责提示                      │
├─────────────────────────────────────────────────┤
│ ④ 策略层：YAML 策略库（core_rules 规则分离）                 │
│     + 回测（沪深300基准）→ 虚拟盘（10万建仓）→ 真钱             │
├─────────────────────────────────────────────────┤
│ ③ 风险层：8红线一票否决 + 风险仪表盘（回撤/集中度）              │
├─────────────────────────────────────────────────┤
│ ② 数据层：7 免费源（mootdx/腾讯/东财/新浪/同花顺/财联社/百度）    │
│     + 大V源（雪球 xueqiu-scraper / 微博 weiboSpider）       │
│     + 行情盯价（Go购 盯价模式复用）                           │
├─────────────────────────────────────────────────┤
│ ① 记账层：双轨（手动录入 + 对账单导入解析——DDD 参考）           │
└─────────────────────────────────────────────────┘
```

## 二、技术选型（基于 17 案例共识）

| 层 | 选型 | 依据 |
| --- | --- | --- |
| 语言/框架 | Python + FastAPI | Go购 经验复用 + daily_stock_analysis 全对齐 |
| 数据库 | SQLite + FTS5（轻量起步） | tech-stack 原则——数据量大了再评估迁移 |
| Agent 底座 | **候选：Agno（全栈）——先用 FastAPI 直写 MVP，底座后置** | 用户要求"先看案例再定"——案例已看完——MVP 不需要底座（规则引擎+信号生成是确定性代码），底座在"大V语义分析/讲解生成"才需要——**MVP 用 LLM 直调（DeepSeek），底座二期评估** |
| 回测库 | 先自写轻量（YAML 策略→历史数据跑）→ 需要时 VectorBT | backtrader 需 A股适配；VectorBT 快 10-100 倍（备查已读） |

## 三、策略库设计（daily_stock_analysis 16 YAML 格式）

```yaml
# 策略模板（core_rules 与策略分离——规则可复用/回测可追溯）
name: ma_golden_cross
display_name: 均线金叉
description: MA5 上穿 MA10（量能确认）——趋势反转/延续信号
category: trend          # trend/reversal/emotion/event/...
core_rules: [1, 2, 3]    # 引用规则库编号（可复用）
required_tools: [get_daily_history, analyze_trend]
aliases: [金叉, 均线金叉]  # 口语触发（"金叉了"→ 本策略）
```

- 规则库（rules/）：买入规则（父母策略翻译）/卖出规则（**第一设计项**）/仓位规则/止损规则
- 策略类别：价值（四大师视角）/趋势（技术分析）/情绪（舆情指数）/事件（政策/解禁/财报）
- **卖出规则列为第一个要设计的规则**（需求 v1.3——父母规则+模糊说法混合）

## 四、信号确认流程（半自动核心）

```
策略触发 → 多视角评审（价值四大师 / 技术多空辩论——2 轮内）
  → 强制结论（通过/不通过/灰色地带 + 价格区间 + 仓位建议）
  → 机械自查（13 项检查：数据2源交叉/Decimal 计算/红线扫描）
  → 推送（详细版：理由+讲解+历史表现+新闻+风险）
  → 你确认（1确认/2忽略/3改价）→ 恒泰手动操作 → 记账
```

- 讲解模式：每个信号带大白话（"为什么触发/指标什么意思"）——观复兼任金融老师
- 低频合并：一天最多 3 条，多的晚报（虚拟盘实测校准）

# 多 Agent 讨论：三阶段演进（2026-08-13 用户确认，勿忘）

> 决策背景：多 agent 讨论价值=防盲点（案例共识：AI Berkshire 四大师/TradingAgents Bull-Bear/BettaFish 论坛/UZI 66 评审团）；风险=结果漂移（可控：强制结论格式+自查 gate+低温度+固定轮次+评分聚合）；用户=最终多视角聚合器（确认流程本身是人工评审）

## 阶段划分（严格按此推进——不许跳阶段）

| 阶段 | 内容 | 时机 | 成本 |
|---|---|---|---|
| **MVP** | 单分析 + 强制结论模板（通过/不通过/灰色地带+价格区间+仓位）——**不做多 agent** | 现在（虚拟盘跑通） | 1 次调用/信号 |
| **二期** | **Bull/Bear 双视角对抗**——信号推送附"多空摘要"（2 agent，最多 2 轮） | 虚拟盘验证后 | 2-3 次调用/信号（DeepSeek flash 便宜可控） |
| **三期** | 四大师/评审团——仅"个股深度研究"触发（不是每个信号都用） | 二期满 1 个月后评估 | 按需（4-66 次调用/研究） |

## 变化控制纪律（贯穿全部阶段）
1. 低温度（0-0.2）+ 结构化输出 schema（pydantic 强制）
2. 固定轮次（讨论最多 2 轮——不无限）
3. 结果聚合用"打分/投票"而非自由文本
4. 同输入→同输出（可复现——AI Berkshire 原则）
5. 讨论是过程，结论是结构化契约——过程可漂移，输出不可漂移

## 为什么这样分（工程判断记录）
- MVP 先验证"规则→信号→确认"闭环——讨论是锦上添花不是地基
- 你的确认流程=最终人工评审——AI 讨论只是喂材料
- 成本递增可控：1→3→按需 次调用/信号
