## 四、信号确认流程（半自动核心）

```
策略触发 → 多视角评审（价值四大师 / 技术多空辩论——2 轮内）
  → 强制结论（通过/不通过/灰色地带 + 价格区间 + 仓位建议）
  → 机械自查（13 项检查：数据2源交叉/Decimal 计算/红线扫描）
  → 推送（详细版：理由+讲解+历史表现+新闻+风险）
  → 你确认（1确认/2忽略/3改价）→ 恒泰手动操作 → 记账
```

- 讲解模式：每个信号带大白话（"为什么触发/指标什么意思"）——观复兼任金融老师
- 低频合并：一天最多 3 条，多的晚报（虚拟盘实测校准）

# 多 Agent 讨论：三阶段演进（2026-08-13 用户确认，勿忘）

> 决策背景：多 agent 讨论价值=防盲点（案例共识：AI Berkshire 四大师/TradingAgents Bull-Bear/BettaFish 论坛/UZI 66 评审团）；风险=结果漂移（可控：强制结论格式+自查 gate+低温度+固定轮次+评分聚合）；用户=最终多视角聚合器（确认流程本身是人工评审）

## 阶段划分（严格按此推进——不许跳阶段）

| 阶段 | 内容 | 时机 | 成本 |
| --- | --- | --- | --- |
| **MVP** | 单分析 + 强制结论模板（通过/不通过/灰色地带+价格区间+仓位）——**不做多 agent** | 现在（虚拟盘跑通） | 1 次调用/信号 |
| **二期** | **Bull/Bear 双视角对抗**——信号推送附"多空摘要"（2 agent，最多 2 轮） | 虚拟盘验证后 | 2-3 次调用/信号（DeepSeek flash 便宜可控） |
| **三期** | 四大师/评审团——仅"个股深度研究"触发（不是每个信号都用） | 二期满 1 个月后评估 | 按需（4-66 次调用/研究） |

## 变化控制纪律（贯穿全部阶段）

1. 低温度（0-0.2）+ 结构化输出 schema（pydantic 强制）
2. 固定轮次（讨论最多 2 轮——不无限）
3. 结果聚合用"打分/投票"而非自由文本
4. 同输入→同输出（可复现——AI Berkshire 原则）
5. 讨论是过程，结论是结构化契约——过程可漂移，输出不可漂移

## 为什么这样分（工程判断记录）

- MVP 先验证"规则→信号→确认"闭环——讨论是锦上添花不是地基
- 你的确认流程=最终人工评审——AI 讨论只是喂材料
- 成本递增可控：1→3→按需 次调用/信号

# 记账交互定案（2026-08-13 用户裁决——勿忘）

## P1-2 已确认：聊天式记账 + 格式规范层

```
你回复"买了 5000 茅台"→ 观复解析 → 回问确认 → 记账
（和信号确认同一种交互——回复 1/2/3 确认，回复"买了X"记账）
```

## 格式规范层设计（防输入错——用户要求）

### 1. 宽松输入模板（记不住也行——模糊也能懂）

```
方向 + 标的 + 金额/数量 + 可选价格
例子：买了 5000 茅台 / 卖 1000 茅台 / 买入 贵州茅台 5000元 @1450
```

### 2. 容错解析（输入错了也能处理）

| 错误类型 | 处理 |
| --- | --- |
| 标的模糊（"茅台"vs"茅台酒"） | 标的库模糊匹配 → 列出候选 → 你选 |
| 单位混乱（5000 元 vs 3.4 股） | 按当前价换算 → 回问确认（"≈3.4 股 @1450？"） |
| 方向漏写（"茅台 5000"） | 默认买入 + 回问确认（不猜） |
| 完全看不懂 | 回格式示例（"没看懂，试试：买了 金额 标的"）——**不静默** |

### 3. 回问确认（防记错账——不可省）

```
记成：贵州茅台 买入 5000 元 ≈3.4 股 @1450？
1 确认 / 2 改 / 3 取消
```

### 4. 双轨兜底（需求 v1.6）

- 日常：聊天式记账
- 月度：券商对账单导入核对（记错账在对账时暴露）

## 1. 大V获取：改手动粘贴起步（原 A 自动抓 → 现 B 手动 + 半自动提醒）

# dsh 借鉴升级点（2026-08-14——架构级吸收 2 项 + 参考 3 项）

**dsh 启发**：session 仅追加事件日志（SessionEvent——持久事实——可重放）
**观复升级**：虚拟盘记账 = **仅追加事件流**（不是传统"持仓表"）：

```
事件: {ts, action: buy/sell/rule_change/signal_ack, symbol, price, qty, reason, ref_signal_id}
```

- 规则修改也记事件（纪律诊断"乱改规则"计数——数据自动有）

→ **MVP 虚拟盘模块按事件日志设计**（比"持仓表"多 10 行代码——省掉诊断/对账/回测三套数据）

### ② 审批策略配置化（半自动确认升级）

**dsh 启发**：审批策略+沙箱框架级（approval policies——可配置）
**观复升级**：信号确认 = **审批策略 YAML**（不是写死在流程里）：

```yaml
审批级别:
  auto_notify: [晨报, 盯价提醒]              # 只推送不确认
  soft_confirm: [买入信号, 卖出信号]          # 推送+确认按钮（可忽略）
  hard_confirm: [止损触发, 大额交易, 规则变更] # 强制确认+讲解+回执
```

→ 策略/信号类型随时调级别——半自动红线可配置化（不用改代码）

# 大V 爬取精读确认（2026-08-14 Pi 接手——xueqiu-scraper + weiboSpider）

## xueqiu-scraper（as167888——雪球）

**机制**：mitmproxy 中间人——启动代理+Chrome → **用户正常访问雪球** → 拦截 HTTPS 响应 → 解析帖子 → SQLite 三表去重（timeline/专栏/个股卡 三通道）
**观复价值**：🟢 **"半自动触发式"**——用户日常浏览雪球时自动采集——**天然防封（正常用户流量不触发 WAF）**——作为**用户浏览顺手采集的补充通道**（非主通道——vpush 自动为主——此通道=人在回路天然采集——零额外成本）
**限制**：依赖用户主动浏览（非全自动）——与 vpush 互补

## weiboSpider（dataabc——微博经典）

**机制**：连续爬取多用户（weibo.cn）——用户信息+微博全字段——txt/csv/json/SQLite 多格式——需 cookie（免 cookie 版=weibo-crawler 同作者）
**观复价值**：🟡 备选确认——**微博主通道=官方 weibo-cli（已定——OAuth 最稳）**——weiboSpider 是官方通道不行时的备选（cookie 维护成本高——与之前判断一致——精读确认技术成熟但维护成本真实）

```
微博：weibo-cli（官方 OAuth）→ 备选 weiboSpider/weibo-crawler（免 cookie）
雪球：vpush（自动——3 天实测）→ 备选 xueqiu-scraper（半自动触发——用户浏览时采）
     → 再备选 timeline-analyzer（XHR hook）
```

## Q11 校准原则（2026-08-17 写定——《深入理解AI Agent》6.10.2/6.2.5/6.5.3 映射）

### 原则一：机制指标 ≠ 目标指标（书 6.10.2）

- **分数是机制**——打分体系/参数是手段；**虚拟盘超额是目标**——体系唯一目标。
- 改打分权重/参数后：**不许拿"打分更合理"当成功**——必须等虚拟盘数据验证（N≥50）才下结论。
- 反例（禁止）："权重调完分数分布更好看了"→ 宣布体系优化。✅ 正例：调完 → 虚拟盘 6-12 月跑超额 → 才算。

### 原则二：护栏指标（书 6.2.5/6.10.2）

- 打分改动必须**双指标看**：目标指标（胜率/超额）↑ **且** 护栏指标（回撤/纪律违反）不恶化。
- 任何改动导致回撤显著恶化（vs 基准 1.5 倍以上）→ 即使胜率上升也回滚。

### 原则三：轨迹前缀回归制度化（书 6.5.3）

- **每个 bug 修复必须带防复发回归测试**——测试内容截断到"出错前缀"（复现错误的上下文片段），不依赖完整流程。
- 判定：修复后测试通过 + 原功能测试不回归（保留集）——才可提交。
- 例：/weekly 路由 bug → test_weekly_report 加路由断言（已实践——制度化为纪律）。

### 原则四：失败归因找首错（书 6.5.2）

- 回测/信号 bug 先定位**首个导致偏离的错误**——后续错误多是连锁反应——不拿最后一个报错当根因。
- 修复后结构化诊断日志（data/diag.jsonl）留档。
