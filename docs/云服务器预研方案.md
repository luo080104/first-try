## 三、部署方案（判定通过日执行——约 2 小时）

```
1. 购机（腾讯云 Lighthouse——2核2G/40G SSD——Ubuntu 22.04 镜像）
2. 环境：Python 3.11 + pip（tushare/akshare/baostock/requests/dateutil）
3. 代码迁移：git clone shopping-agent 仓库（观复部分）
4. 数据迁移：data/ 下账本+缓存（~500MB——scp 或 git-lfs）
5. 凭证：.env（tushare token/Server酱 key）——scp 手动传，不入 git
6. 定时任务：crontab 或 systemd timer：
   17:00 日报 / 16:00 雪球 / 16:05 微博 / 周五 15:30 周报 / 每 30min 看门狗
7. 看门狗自检：云端看门狗查云端任务 LastRunTime（同架构——直接复用）
8. 验证：跑一次 audit_judgment + 一次日报实弹（微信收到）
```

**关键决策**：

- **Linux 而非 Windows**——crontab 比任务计划简单且免费，无电池策略坑（8/17 教训）
- **代码只读同步**——云端是"执行者"，本地是"开发+裁决"（改动在本地测好→git push→云端 pull）
- **数据双向**：云端跑任务写账本→每日 git 提交回本地仓库（或本地拉取）——裁决/审计永远在本地做

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 云端挂了没人知道 | 看门狗设计成**双端互查**：云端查自己任务+本地看门狗查云端 LastRunTime（本地每天开机时会告警）|
| 数据分叉（本地/云端账本不一致）| 单一事实源=云端（执行）+每日 git 提交归档；本地裁决只读 |
| 云端 IP 被数据源封 | 观复数据源全 HTTP 免登录（tushare token 白名单）——风险低；真被封则换地域重建（数据全在 git——重建 <30 分钟）|
| 忘记续费 | 设日历提醒+续费同价 1 次（第 2 年可能涨价——届时重新比价）|
