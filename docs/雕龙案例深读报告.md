## 一、oh-story-claudecode（追踪系统——雕龙⑦核心参考）

### 单一权威事务模型（O(1) 的关键）
- `追踪/_tracking-state.json` = **唯一结构化权威**（不进正文 prompt）
- 所有派生视图（上下文.md/角色快照/伏笔.md/作者真相/读者已知）由 `tracking_commit.py` **确定性派生**，程序**不反向解析 Markdown**
- **提交顺序**：渲染 delta → 写逐章记录 → 写派生视图 → **最后原子写 _tracking-state.json**（单提交点；此前失败可重跑同一事务）

### tracking_commit.py 实现要点（1139 行，已读）
- `atomic_write_text`：mkstemp → fsync → os.replace（原子）
- `write_if_changed`：内容相同跳过（省 IO）
- 容量控制：逐章记录 ≤1536B（硬上限 3072）、上下文卡 7 栏 ≤12KB、快照 ≤8KB
- 输入校验：`require/as_*`/`clean_text`（UTF-8 字节上限）/`require_known_keys`（未知字段拒绝）
- Windows 兼容：`emit` 用 buffer 写 UTF-8（绕 cp1252——我们 GBK 坑同款）
- 文件名安全：Windows 保留名（CON/NUL）检查
- `check_project`：delta 连续性 + 文件名规范 + 派生视图与 state 完全一致

### 状态卡 7 栏（续写注入 ≤12KB）
当前位置 / 长期约束 / 核心角色状态 / 活跃伏笔 / 近三章速记 / 下一章承诺 / 连贯性风险

### 双时间线
作者真相 vs 读者已知（作者秘密不泄露到读者视图）

## 二、sumeru（编排+审查——雕龙②④⑦核心参考）

### worldbuilder 主控编排（473 行 SKILL.md）
需求收集 → topic → outline（完整章节细纲）→ **检查点1** → write（并行 3章/Agent）→ **检查点2** → review（自动修复）→ **检查点3** → polish → finalize
- **3章/Agent 硬约束**（所有章节级操作：细纲/写/审/润/终稿）
- 每阶段检查点验证才进下一阶段
- 状态持久化：.sumeru/session|topic|outline|write|review/（断点续传）

### review 三阶段（218 行）
1. **全局审查**：脉络/时间线/设定一致/OOC/伏笔回收（5 项）
2. **章节并行审查**：每章概要 + 问题清单（3章/Agent）
3. **统一修复**：轻量（直接改+备份 original）/ 严重（自动修订大纲+重写章节）/ **底线问题零遗漏**（六类：设定崩坏/OOC/重复情节/信息泄露/伏笔死结）
- 输出：fix-plan.json + outline-revisions.json + bottom-line-checklist.json

## 三、novel-writing-framework（质检——雕龙⑥核心参考，500+ 章实战）

### 8 条全局铁律
1. AI 句式"不是X是Y"≤2次/章（663→31 次清洗教训）2. 正文元话语禁令（卷一/第X章/前文/本章）3. 连续3章同场景必须切换 4. 长线悬念间隔≥2章 5. 感叹号+粗口初稿到位 6. 角色语音卡 7. 破折号脚本批量替换 8. **三章一轮 AI 扫描**（不攒 50 章）

### 硬性指标（双平台通用）
CJK≥2000/章 | "不是X是Y"≤2（正则 /不是[^—]{2,30}——是/）| 元话语 0 | 模板段落 0 | 章节差异≥1 独特场景 | 重复形容词≤3 | 段落≤200字 | 破折号≤20

### AI 口水词清单
缓缓/不由得/眼底闪过/心中升起/说不出的/这意味着/他的眼神/深邃/不可置信……

### 十维评审（每章/单元/卷 ×10 分）
开篇吸引/人物深度/情节节奏/…（结构化评分体系）

### 平台差异（雕龙要支持起点+番茄）
| 维度 | 番茄 | 起点 |
|---|---|---|
| 读者耐心 | 3秒划走 | 慢热设定 |
| 爽点 | 3章一爽 | 10章铺垫 |
| 主角 | 全程碾压 | 允许犯错 |
| 变现 | IAA 广告 | 订阅 |

### 算法适配（番茄）
首章完读率⭐⭐⭐⭐⭐ / 前3章完读率（脑洞≥15%）/ 章节连续点击率（比收藏重要10倍）

### 实战铁律补充
1-5章必须有正面爆发 | 每10章≥1次碾压 | 战斗承诺必须兑现（#1差评）| 单元终章危机钩子

## 四、webnovel-writer（一致性系统——雕龙整体架构参考）

### 定位
"写到几百章依然记得住设定、接得住伏笔、守得住大纲"——一致性系统不是生成器

### 核心命令（8 skill）
init/plan/write/review/query/learn/dashboard/doctor

### write-gate + chapter-commit
动笔前查资料 → 写 → 审查 → 润色 → **记录事实** → 自动备份（一章一个事务）

### Story Repo 规格 v7（最重要设计——雕龙存储参考）
1. **一本书 = 一个 git 仓库**；接受一章 = 一次原子 commit
2. **文件即真相**：全部状态人可读 Markdown/YAML，系统检测手改并提议结转，永不报错
3. **派生物可丢弃**：删 .cache/ 后从源文件全量重建（CI 验收项）
4. **定稿只增不改**：已接受章节不可逆改；改设定走显式 retcon 事务
5. **升级原则**：脚本 < 模型 < 作者（能数的不让模型估，能模型判的不打扰作者）
6. **对话即编辑器**：任何结构化修改可用一句自然语言（作者无须学文件格式）
7. 容错读取：未知字段保留原样写回（不丢扩展数据）
8. 中文目录（作者全中文：定稿/大纲/文风/工作区）

### 作者友好报告（雕龙缺的）
三段式报告（总状态+里程碑+下一步）| 错误分类（已自动处理/建议确认/必须处理）| 技术细节默认隐藏 | 术语翻译
