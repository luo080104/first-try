# 盲审报告（独立第三方 · 只读）

审查范围：tools/strategy_engine/ 的 portfolio.py / gate_check.py / strategy_score.py / core_loop.py / notify_gf.py（另核对 data.py、filters.py、attribution.py 等依赖）。未运行代码，全部结论来自静态证据。

## 盲审发现（按严重度排序）

### 🔴 严重

1. **通过判定结构上不可达（周对齐错配）** gate_check.py:258-259 用 `_week_last_day()`（:351）把 ISO 周键映射到**周日**，再与 `bs_kline_weekly("000300",10)`（:222）的基准周线匹配。baostock 周线 date 为当周**最后交易日（通常周五）**（data.py:106-112 原样透传），周日查表必落空 → 每对周被 continue → `wins` 恒 0 → "4 周跑赢"分支永不触发；而 :198-204 F5b 已废除 90 天保底同样返回不通过。**passed=True 无任何可达路径**，判定形同虚设。建议：改用基准日期键直接对齐，或把周键映射到当周最后交易日。

2. **Alpha 三态判断塌缩** gate_check.py:293-300：`alpha_ok = att.get("alpha_positive") is not None and att["alpha_positive"]`。归因数据不足时 attribution.py:75/109/118 返回 `alpha_positive=None`，此时 alpha_ok=False → `if alpha_ok == False` 命中 → 以"Alpha 为负——疑似 Beta 驱动"为由阻断（:298-300）。注释声称"None 数据不足"、docstring 声称"归因不足不阻断判定"，实际把**未知当为负**并输出错误理由。应改为显式 `if att["alpha_positive"] is False:`。

3. **B3 信号绕过硬否决** core_loop.py:265 先过滤 vetoed 候选，:268-273 却对全部 candidates 追加 B3 信号——被 N 不买清单/红线否决的股票只要触发 B3 照样入确认队列并推送（:283-292），直接违反 strategy_score.py:6-7"烂票永远 0 分"，且 B3 路径不查 failed_pool 黑名单。建议 B3 入队前复用同一 veto 检查。

### 🟡 中等

4. **红线空跑** core_loop.py:245-249 调 score_stock 未传 redlines → strategy_score.py:238 `redlines or {}` → filters.py:165 的 R1-R8 全为 no-op。注释"不再空跑桩"（strategy_score.py:234）与事实不符。未接线或删注释。

5. **CLI 谎报"不阻止"** portfolio.py:412 约束失败打印"不阻止——记录事件供确认"，随后 buy()（force=False 默认，:113）内部再查约束并返回 False、不记事件——实际阻止且零记录；CLI 也无 force 通道。

6. **price=0 标 real** portfolio.py:385 腾讯兜底 `q.get("price") or 0` 标 `"real"`，而 data.py:227 字段缺失即返回 price 0。positions()（:164-165）回退成本价，但 record_equity 三态只看 data_state（:214-221）→ 成本价点被当 real 计入净值并参与判定。应 `price<=0` 标 fallback。

7. **门槛口径漂移** strategy_score.py:19-22 门槛 84/96/106（120 制），但模块 docstring（:5）仍写"低潮 70/正常 80/高潮 88"；core_loop.py:203 兜底默认 80（120 制下 67%——恰是注释声称修复的语义漂移）。

8. **基准窗口截断+残留文案** gate_check.py:222/230 仅取 10 周基准，组合运行更久时早期跑赢周被静默丢弃；:342 文案"满 90 天也通过"与 F5b（:23, :198）矛盾。

### 🟢 轻微

9. portfolio.py:283 docstring"按当前市值占比"，实为成本价口径（:272，positions 无 quotes 亦用成本价）。
10. core_loop.py:214-216 每只股票重复 load_leader_pool()（重读 YAML），pool 已在 :207 加载。
11. portfolio.py:102 force 通道声称"reason 需注明 OVERRIDE"，代码未校验。
12. portfolio.py:168-170 止盈卖出也进 failed_pool 黑名单，买回被 check_rebuy 拦截，语义待确认。

## 与项目自评的差异

- progress.md 宣称"M1.5 达成、晨报雏形真实验证"；核心交付物 gate_check 的通过判定存在上述 1、2 两条结构性缺陷（不可达+误判），未见相应测试覆盖证据。
- gate_check.py:5-9 模块 docstring 仍称"满 3 个月未 4 周连胜也通过"，与 F5b 落地（:198）直接矛盾。
- "红线不再空跑桩"注释（strategy_score.py:234）与 core_loop 实际调用不符（见 4）。

## 盲审总评

工程细节扎实（原子写盘、事件日志、幂等净值、容错红线均有落地），但判定链核心存在"不可达 + 三态塌缩"两类逻辑缺陷，硬约束存在 B3/force/空跑三条可绕过路径，多处 docstring 与行为矛盾。数据可信度（price=0 标 real）与口径（成本 vs 市值）亦有瑕疵。

**评分：5.5 / 10**（工程 8 分 × 判定可信度 4 分 × 约束生效 6 分）
