> v1.3→v1.4：P0 落地决策（样本/仓库/平台/MVP 边界）
> v1.2→v1.3：InkOS + Arboris-novel + AI_NovelGenerator + ECC

## 定位

面向中文网文作者的全流程 AI 创作副驾驶。核心差异化：**学习指定作家的风格指纹，写出"像那个人"的文字。**

**首版标的**：滚开经典三本——《神秘之旅》《极道天魔》《永恒剑主》（前 200 章/本）
**验证集**：《苟在武道世界成圣》（已被市场验证的模仿品，用于盲测风格引擎精度）
**首版平台**：起点中文网（先单平台跑通再分化）
**仓库**：`diao-long`（luo080104 已建，需从 `-` 改名）
**前端策略**：先 CLI 跑通核心流水线，后端稳了再套界面

## 8 个自动化 Hook（学 oh-story）

| Hook | 触发时机 | 效果 |
|------|---------|------|
| **guard-outline-before-prose** | ④ 写手生成章节前 | 🔥 细纲不存在 → 阻断，不生成正文 |
| **check-prose-after-write** | 每章落盘后 | 毒句式/截断/AI自指硬信号兜底扫描 |
| **detect-story-gaps** | 每次启动会话 | 检测设定缺口、大纲缺失、伏笔断线 |
| **pre-compact** | 上下文压缩前 | 保存进度快照（当前章号+已写字数） |
| **post-compact** | 上下文压缩后 | 自动加载进度快照恢复上下文 |
| **validate-story-commit** | git commit 时 | 检查硬编码属性、设定必填字段 |
| **backup-before-write** | 任何文件修改前 | 🔥 cp 到 `.dragon/original/<file>.<ts>.bak` |
| **backup-before-rewrite** | ⑦ 自动重写章节前 | cp 到 `.dragon/original/rewrite/` |

## 各模块详细设计

### ① 市场分析师
**输入**：题材类型 + 可选平台
**过程**：浏览器爬取起点/番茄榜单 → LLM 分析热度/赛道/变现
**输出**：`选题报告.md`

### ② 架构师
**输入**：选定的选题方案
**过程**：
- 世界观构建 + **中式节拍引擎**（替代西式 beatsheet）：
  - **黄金三章**（前 6000 字）：世界观建立 + 第一次爽点 + 阶段性成果
  - **阶段突破点**（每 30-50 章）：战力升级节点
  - **面板更新频率**（每章或每 3 章）：系统面板格式校验
  - **卷间转折点**
- 卷纲 → 章纲 → 细纲（每章 3-5 个关键情节点）
- **每章 hook_statement**（章末钩子——"本章结尾读者必须想问什么"）
- **平台分化**（学 novel-writing-framework）：
  - 番茄：3章一爽、主角碾压、撕裂式情感
  - 起点：可10章铺垫、允许主角恐惧/犯错、群像展开
**输出**：`设定集/` + `chapter-outlines.json`（含 hook_statement + 平台策略标签）
**验证门**：细纲完整性——总章数≥20、每章情节点≥3、hook 覆盖率 100%

### ③ 角色工坊
**输入**：世界观 + 故事大纲
**过程**：
- **15 维静态 DNA**：童年创伤/核心恐惧/内心渴望/说话习惯/身体语言/思维模式/决策方式/隐藏秘密 + 七人格框架交叉分析
- **3 段动态弧线**：初始自我欺骗 → 中点转折事件 → 终点状态
- 角色关系图谱 + 每个角色语音卡（模板句 + 禁用词 + 口头禅）
- 情绪引擎：6 种情绪 × 1-10 强度 × 章节情绪曲线
**输出**：`角色档案/` 目录

### ④ 写手池
**输入**：`chapter-outlines.json` + 角色档案 + 风格规范
**过程**：
- **相邻章节同 Agent**（学 sumeru）：Agent1=1-3章，Agent2=4-6章……尾部不足3章按实际分配
- 所需 Agent 数 = ceil(总章数 / 3)，调度器自动计算
- 写前守卫：细纲存在？→ 注入上下文（追踪系统返回的上章状态）→ 开工
- 滚开风格约束（算账叙事模板：问题→备战→算账→执行→结算）
- **continuity_check**：每个 Agent 写完 3 章后，交叉校验相邻章的首尾衔接
- 写后自动进入⑤→⑥内循环
- **多版本对比**（学 Arboris-novel）：同一章可生成 2-3 个版本，挑最符合风格指纹的进入润色——不是"改"，是"选"
- **不要怕并行**：Reasonix 实测子 Agent ¥0.017/个，100 章不到 ¥2
- **每章控制面文档**（学 InkOS）：写完即生成四份复盘文件——
  - `chapter-XXXX.intent.md`：本章目标、保留项、避免项
  - `chapter-XXXX.context.json`：本章实际选入的上下文
  - `chapter-XXXX.rule-stack.yaml`：应用的优先级规则层
  - `chapter-XXXX.trace.json`：输入编译轨迹（可复现、可审计）
**输出**：`chapters/第N章.md` + `chapters/` 原始备份 + `runtime/` 控制面文档

### ⑤ 风格引擎（核心差异化）
**输入**：滚开全部作品（笔趣阁精校 txt）
**过程**：
1. **统计指纹提取**（学 InkOS `style analyze`）：Voiceprint + nuwa 联合提取风格指纹（功能词频率/句长/标点/战斗模式/面板模板/爽点节奏）→ 生成风格规范文件
2. **不可变前缀设计**（学 Reasonix）：system prompt + 工具定义 + 风格规范放在请求最前面且**一字不动**
3. **多模型任务路由**（学 AI_NovelGenerator）：②④⑤→Pro（质量），⑥⑧→Flash（便宜），①③→Pro
4. 六层润色 + **反检测模式**（学 InkOS `revise --mode anti-detect`）：独立于润色的专项——词汇疲劳词表+禁用句式+文风指纹注入
**输出**：`chapters/第N章.md`（已润色+反检测通过）

#### 滚开模式"算账叙事"模板
```
每章结构：
1. 问题引入（反派等级×人数）
2. 备战（主角获取新技能/等级提升）
3. 算账（主角战力 vs 反派战力）
4. 执行（战斗描写，占全章 ≥30%）
5. 结算（面板更新 + 新威胁预告）
```

### ⑥ 量化质检师
**输入**：润色后的章节
**过程**：
- **8 条全局铁律**（学 novel-writing-framework）：
  1. 禁止元话语（"卷一""前文""后文"不出现在正文）
  2. 场景轮换 ≥ 5 个
  3. 长线钩子不连续 3 章重复
  4. 感叹号/粗口初稿就放，后期不补
  5. 正文不出现"第X章"标记
  6. 角色对话不串音（每人有自己的语音卡）
  7. 战力体系不自相矛盾
  8. 爽点密度：每 3 章至少一个
- **13 项硬性量化指标**逐章扫描：
  1. CJK 字数 ≥ 2000/章
  2. 破折号 ≤ 20/章
  3. "不是X而是Y" ≤ 2/章
  4. 场景数 ≥ 5 个轮换
  5. 章节字数偏差 ≤ 目标字数的 15%
  6. 对话占比 20-40%
  7. 战斗场景占比 ≥ 30%（滚开模式）
  8. 系统面板至少出现一次
  9. 章末钩子明确可识别
  10. 感叹号密度 ≤ 5%（非战斗章）/ ≤ 10%（战斗章）
  11. AI 句式扫描通过（"值得注意的是""总的来说""此外"等自动计数）
  12. 角色对话差异化（相邻角色的对话风格差异 ≥ 阈值）
  13. 情节推进量（每章至少一个可识别的新增信息/状态变化）
- **三章一轮阻断**（学 novel-writing-framework）：
  - 每 3 章停笔自检 → 任何一项不通过 → 退回 ④ 重写（max 3 次）
  - 3 次仍不通过 → 标记"人工介入"
  - **663→31 的教训**：10 章一轮太迟，三章一轮第一轮就暴露问题
**输出**：`质检报告.md`

### ⑦ 追踪审查员（v1.2 重大升级）
**三阶段审查修复流程**（学 sumeru）：

**第一阶段：全局审查**
- 加载完整大纲和细纲建立基准
- 分析整体剧情脉络、时间线、伏笔回收、冲突分布
- **六类底线问题扫描**（不全解决不闭圈）：
  1. 时间线矛盾
  2. 设定崩坏（战力体系前后不一致）
  3. 人物 OOC
  4. 重复情节
  5. 信息泄露（角色知道不该知道的）
  6. 伏笔死结
- 输出：`global-issues.json` + `bottom-line-checklist.json`

**第二阶段：并行章节审查**
- 3 章/Agent 并行（相邻章节同 Agent）
- 每章检查：字数/时序/OOC/物品状态/场景质量/伏笔
- 输出：`chapter-issues/` + `summaries/`

**第三阶段：统一修复**
- 合并问题按严重度排序（致命 > 严重 > 中等 > 轻微）
- **轻量修复**：文字修正/段落调整/字数填充 → 直接改 chapters/（前自动备份）
- **严重问题闭环修复**（学 sumeru）：
  - 剧情矛盾/大面积 OOC/设定崩坏 → **自动修订 chapter-outlines.json 中对应细纲** → 子 Agent 并行重写对应章节（前自动备份）
- **底线问题零遗漏核验**：逐一核对六类底线问题，全部标记"已解决"或"需人工干预"后审查流程才允许结束
- **文件即真相**（学 oh-story）：追踪状态不存 SQLite，存 Markdown 文件
  - `追踪/上下文.md`（O(1)——永远 ~1.2KB，不随章数膨胀）
  - `追踪/伏笔.md`
  - `追踪/时间线.md`
  - `追踪/角色状态.md`
  - `追踪/叙事承诺.md`
  - `追踪/质检进度.md`
- **9 类事实自动提取**（学 InkOS Observer）：每章落盘后自动从正文抽取——角色/位置/资源/关系/情感/信息/伏笔/时间/物理状态 → 写入对应追踪文件
**输出**：`fix-plan.json` + `审查报告.md` + `追踪/` 状态更新

### ⑧ 诊断分析师
**输入**：全本或指定章节范围
**过程**：五阶段流水线 → 全本情绪曲线/节奏曲线/人物图谱/爽点热力图/伏笔回收率
**输出**：`诊断报告.md` + 可视化图表包

### ⑨ 出版师
**输入**：定稿的全部章节
**过程**：
- **平台分化导出**（学 novel-writing-framework）：
  - 番茄：短段落/高密度爽点/广告分成全勤适配
  - 起点：章节订阅格式/慢热铺垫保留/付费章节分割
- 三级敏感词检测 + 错别字/标点/语法自动修正
- 手机阅读自动分段优化
**输出**：`publish/起点/` + `publish/番茄/`

## 爬取与风格指纹提取

### 学习样本
- **滚开经典三本**：《神秘之旅》《极道天魔》《永恒剑主》，每本前 200 章
- stylometry 领域 3-5 本同时期作品是最优样本量，更多引入噪声
- 源：笔趣阁精校版 txt
- 工具：复用 Go购 browser_pool + FictionDown 站点解析规则

### 验证集
- **《苟在武道世界成圣》**：已被市场验证的滚开风格模仿品
- 用法：Voiceprint 提取经典三本指纹后，系统生成的章节与此书做盲测对比
- 指标：句长分布偏差/战斗占比/面板频率/"不是X而是Y"计数
- 如果系统输出和模仿品接近 → 风格引擎方向正确

### P0 静态风格规范文件（非完整 Voiceprint）
P0 阶段不跑完整指纹提取流水线，先人工整理一份 `风格规范.md`：
```markdown
# 滚开风格规范

## 面板模板
【姓名：XXX】
【等级：XX】
【功法：XXX（第X层）】
【技能点：XXX】

## 禁用词
- 值得注意的是 / 总的来说 / 此外 / 不言而喻
- 不是……而是……（≤2/章）
- 过度使用破折号（≤20/章）

## 代表性原文摘录
（粘贴极道天魔第3章、第15章、第50章各 500 字）
## 算账模板
问题引入(反派等级×人数) → 备战(新技能) → 算账(战力对比) → 执行(战斗≥30%) → 结算(面板更新+新威胁)
```
P1 阶段切换为完整 Voiceprint + nuwa 联合提取。
1. 功能词频率谱 2. 句长分布 3. 标点指纹 4. 战斗描写模式
5. 系统面板模板 6. 爽点节奏（压制→蓄力→爆发） 7. 禁止词汇表
8. 章节结构模式（问题→备战→算账→执行→结算） 9. 数值展示频率

### 声音保真度盲测
写完一卷后，取滚开原文同位置的一卷，并排对比：
- 句长分布偏差 ≤ 15%
- 战斗场景占比偏差 ≤ 10%
- 系统面板频率偏差 ≤ 20%
- "不是X而是Y"句式 = 0
- CJK 字数偏差 ≤ 10%

## 关键设计决策

| # | 决策 | 来源 | 为什么 |
|---|------|------|--------|
| 1 | 追踪状态用 Markdown 不用 SQLite | oh-story | git 可追踪、肉眼可读、崩溃不丢、O(1) 膨胀 |
| 2 | 修改前自动备份 | sumeru | 改坏了能一键回滚 |
| 3 | 严重问题自动修订大纲+重写 | sumeru | 不只发现问题，还自动修复 |
| 4 | 相邻章同 Agent + 每 Agent ≤ 3 章 | sumeru | 上下文连贯 + 并行效率最优 |
| 5 | system prompt 不可变前缀 | Reasonix | 缓存命中率从 55% → 80%+ |
| 6 | 写前守卫阻断 | oh-story | 没细纲不写正文——强制纪律 |
| 7 | 三章一轮自检 | novel-writing-framework | 10 章一轮让 663 处 AI 指纹漏过去 |
| 8 | 每章 hook_statement 必填 | 图书联合作者 | 章末钩子是网文的命 |
| 9 | 8 条全局铁律 + 13 项量化指标 | novel-writing-framework | 可机器执行的质量底线 |
| 10 | 平台分化写作 | novel-writing-framework | 番茄快节奏 vs 起点慢热，同大纲两套写法 |
| 11 | 每章控制面文档（intent/context/rule-stack/trace） | InkOS | 可审计、可复现——知道"为什么这章写成这样" |
| 12 | 多版本对比（生成2-3版择优） | Arboris-novel | 不是改出来的，是选出来的 |
| 13 | 多模型任务路由（Pro→质量/Flash→便宜） | AI_NovelGenerator | 架构用Pro，质检用Flash——精准分配 |
| 14 | 反检测模式（revise --mode anti-detect） | InkOS | 润色之外的专项——读者会不会看出AI写的 |
| 15 | 9类事实自动提取（Observer） | InkOS | 每章落盘自动更新角色/位置/伏笔/时间状态 |
| 16 | 门禁前置（fail-closed） | ECC | 安全默认拒绝——不确定的宁可阻断不冒险 |

## 数据流与存储（文件即真相）

```
{书名}/
```

### 技术栈
- 后端：Python + FastAPI
- 存储：Markdown 文件（状态） + SQLite（向量检索缓存） + Chroma（嵌入向量）
- **缓存层独立模块**（学 Reasonix：不被业务逻辑干扰前缀稳定性）
- 浏览器池：DrissionPage（复用 Go购）
- 模型：DeepSeek-V4-Pro（主推理）
- 前端：PWA 网页
- 子 Agent 并行：ceil(总章数/3) 个 Agent，实测成本 ¥0.017/Agent

### MVP 边界
- **3 章**：②生成细纲 → ④写前三章 → ⑥质检通过
- P0 不含完整风格引擎——用静态规范文件锁定方向
- P0 不含前端——CLI 运行，Go购 的 PWA 前端经验留到 P5 复用
- 起点单平台，番茄分化押后到 P4
