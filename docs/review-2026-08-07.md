## 二、设计决策审核（第三部分）

### 决策1：SKU 匹配用"品类适配器"模式 → ✅ 合理

每品类一套参数规则（服饰→款号 / 食品→规格 / 电脑→配置），这是正确的设计。

**原因**：不同品类的"同一商品"定义完全不同。羽绒服的"同款"看品牌+款号+颜色；牛奶的"同款"看品牌+规格（250ml×12）；笔记本电脑的"同款"看品牌+型号+GPU+内存+存储。用一套规则硬套所有品类会匹配错乱。

**补充建议**：阶段 1 先实现 1-2 个品类的适配器（服饰 + 食品），跑通后再扩展。不要一开始就设计所有品类。

### 决策2：阶段1"品牌+标题前缀"最简匹配，阶段2完善 → ✅ 渐进路线 OK

**评价**：完全正确。阶段 1 的目标是跑通"搜索→存库→展示"闭环，不是匹配精度。先用最简匹配，有数据后再迭代。

**风险提醒**：品牌名可能跨平台不一致（如"波司登"vs"Bosideng"），但阶段 1 不用管，阶段 2 再做品牌归一化。

### 决策3：存库方案 B（商品+SKU+价格全链路）vs 只存价格 → ✅ B 不过度设计

**评价**：三级结构（products → skus → price_history）是价格追踪系统的标准设计，不是过度设计。

**原因**：
- 只存价格 → 无法按商品聚合跨平台比价（不知道哪条价格属于同一商品）
- 有 products 表 → 才能做"波司登羽绒服在各平台的价格对比"
- 有 skus 表 → 才能区分同款不同色/不同配置
- price_history → 每次搜索都记录，才能画价格趋势曲线

pi 的 schema.sql 10 张表设计合理，specs 用 JSON 存品类特有参数也很灵活。继续保持。

### 决策4：测试商品选波司登/金典牛奶/洗衣液 → ✅ 合理

**评价**：三个品类覆盖了不同匹配难度：
- 波司登羽绒服（品牌强、款号明确）→ 容易匹配
- 金典牛奶（规格标准化）→ 中等难度
- 洗衣液（品牌分散、规格多样）→ 难匹配

**发现的问题很有价值**：
- 蓝月亮搜不到 → 揭示了联盟 API 只返回有佣金商品的覆盖盲区
- 金典牛奶只返回1条 → 食品类佣金商品少
- 这些是真实限制，接受是对的

### 决策5：命令行先行、网页版放阶段4 → ✅ 节奏合适

**评价**：正确。CLI 先验证核心逻辑（搜索→匹配→存库→比价），逻辑跑通了再套 UI 壳。对编程小白来说，降低复杂度很重要。

## 三、联网查证结果（第四部分）

### 查证1：大淘客京东/拼多多搜索接口 → ⚠️ 有重要修正

**⚠️ 关键发现：大淘客没有京东搜索接口！**

大淘客各平台 API 能力对比：

| 功能 | 淘宝 | 京东 | 拼多多 | 抖音 | 唯品会 |
|------|:----:|:----:|:------:|:----:|:------:|
| 商品搜索 | ✅ | ❌ | ✅ | ✅ | ✅ |
| 商品列表 | ✅ | ❌ | ✅ | ❌ | ✅ |
| 商品详情 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 推广转链 | ✅ | ✅ | ✅ | ✅ | ✅ |

京东在大淘客只有：商品详情、推广文案、链接解析、订单查询。**没有搜索和列表功能。**

**拼多多搜索接口**（可用）：
- URL：`https://openapi.dataoke.com/api/dels/pdd/goods/search`
- 方法：GET
- 主要参数：
  - `keyword`（关键词，必填）
  - `page`、`pageSize`（分页）
  - `sortType`（排序：0默认/1佣金升/2佣金降/3销量升/4销量降/5价格升/6价格降/9券后价升/10券后价降）
  - `withCoupon`（0全部/1仅有券）
  - `catId`、`optId`（分类过滤）
  - `pid`（拼多多推广位PID）
  - `customParameters`（自定义参数）
  - `isBrandGoods`（是否品牌商品）
  - `rangeList`（价格区间）
- 需要 PDD 授权：在 dataoke.com/shouquan 获取拼多多授权ID

**结论**：
- 拼多多比价：用大淘客 PDD 搜索接口，需要绑定多多进宝 PID
- 京东比价：不能用大淘客，只能等京东联盟应用审核通过后用京东自己的 API
- pi 提到的 `dels/jd/goods/search` 不存在，需修正

### 查证2：服饰 SKU 跨平台匹配方案

**可行方案**（从简到难）：

1. **阶段1（现在）**：品牌+标题前缀匹配 — pi 已在做，够用
2. **阶段2（下一步）**：正则提取款号+颜色+尺码
   - 服饰商品标题通常包含款号（如"466789"）或型号编码
   - 用正则 `\d{6,}` 提取数字款号
   - 颜色/尺码用关键词词典匹配
3. **阶段3+（进阶）**：语义相似度匹配
   - 用 StructBERT 或 GTE 模型生成标题向量
   - 计算余弦相似度，>0.85 视为同款
   - 已有开源案例：5000条标题去重，准确率96.3%
   - 但需要部署模型，对个人项目偏重
4. **实用折中方案**：用 DeepSeek API 做标题归一化
   - 输入两个平台商品标题，让 LLM 判断是否同款
   - 不需要部署模型，适合你的技术栈

**建议**：阶段2 先用正则提取款号，匹配不上的再用 DeepSeek 辅助判断。
