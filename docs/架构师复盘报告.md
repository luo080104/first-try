## 〇、一句话结论

**观复是我见过的个人项目中，罕见的"验证纪律压倒开发冲动"的系统。** 它的价值不在代码量（163 测/31 文件——中等），而在三件事：①把"未经证实的观点"隔离在策略之外（Q6 红线）；②把"人"正确地留在决策环里（半自动）；③把每次失败变成文档化的教训（运维七章）。但它的结构性风险也清晰：**单一策略依赖 + 免费数据源脆弱 + 验证周期远长于决策周期**——这三者决定了观复的上限，而不是代码。

# 第一部分：四问深答（题外话——架构师视角）

## Q1：观复的核心链路是什么？

**定义：观复的核心链路是一条"信任传递链"——每个环节都在把上一环的结论"降级风险"后传给下一环：**

```
数据（全自动——可信度最高，机器无情绪）
  → 策略信号（规则+回测背书——半可信）
  → 风险层（8 红线一票否决——只做减法）
  → 人工确认（信任边界——人在此接管）
  → 执行记账（双轨可审计）
  → 验证回流（净值→归因→校准——闭环回到策略层）
```

**架构师判断**：

- ✅ 链路设计**正确**：核心不是"数据流"而是**信任边界**——越接近钱，自动化越低。这是 Agent 系统最容易被做错的地方（自动交易/LLM 直接下单），观复没有错
- ⚠️ 链路**弱点**：策略层是单点（B3 依赖）——链路前 60% 都建立在单一信号上；验证回流（最后一环）周期太长（4 周判定 vs 策略真验证 1 年+）——**链路是"生产导向"的，不是"验证导向"的**

## Q2：每个卡点怎么验证？

**观复的验证是"金字塔形"——方向对，塔尖缺两块石头：**

```
       真钱（2-3 万——验证冲击成本）      ← 塔尖：实盘偏差对照（Q10）未设计
     虚拟盘（4 周+Alpha>0——验证执行）    ← 9/12 判定——但缺"风格对照基准"
    回测（10 年后复权+成本——验证规则）   ← 已定案——但"信号类型归因"未分层
   单测（163 个——验证代码）              ← 扎实
```

- ✅ 四层都真实存在且**每层有"不通过就停"**（防未来函数/涨跌停不可成交/Alpha>0）——比多数个人项目严谨一个数量级
- ⚠️ **两个真缺口**：
  1. **虚拟盘判定只对照沪深300**——没对照"红利低波指数"——如果组合跑赢是风格 Beta（红利十年牛），Alpha 判定会被污染（架构师 Q1 核心担忧）
  2. **M2-2"连续 2 周无人工干预"从未正式核验**——spec 有标准但没人执行过（验收清单 2026-08-16 发现——定 8/30 复核）

## Q3：能不能优先用 API？

**必须优先——而且已经做到了。** 原则：**稳定性 > 丰富性**。浏览器爬虫（Playwright/DrissionPage）= 隐性炸弹（WAF 滑块/页面改版/登录态过期）。观复现状：**零浏览器依赖**——行情/估值/财务/资金流（腾讯/baostock/akshare/tushare）+ 大V（雪球 requests 直调 4 接口 + 微博官方 weibo-cli）——2026-08-16 刚把最后一个浏览器依赖（大V 调仓）API 化。**边界**：API 拿不到的（大V 观点语义/盘面情绪）→ 不做或人工——不为丰富性引入脆弱性。

## Q4：spec 有没有成功标准？

**有，但犯了 spec 常见病——"成功标准写在文档里，没长在流程上"。**

- ✅ 有：M1（回测可复现）/M2（虚拟盘闭环）/M3（推送全链路）+ 虚拟盘 4 周判定——且都是"可证伪的验收"
- ⚠️ 三个问题：①**分散**（M 标准在技术方案.md，判定在落地实施.md——没人对照）②**过期**（M2"10 万"→已改 8 万未同步）③**无执行钩子**（M2-2 标准存在但从未核验——标准没有"验收人+验收时间"就是纸面标准）
- ✅ 已建 `docs/观复验收清单.md` 解决（每项=标准+证据+状态）——**把 spec 从"文档"变成"流程"**

# 第二部分：全项目复盘

## 一、项目本质：它到底是什么

**观复不是"自动交易 Agent"，是"决策支持系统 + 行为约束器"。** 这个定位正确且罕见清醒。对比：自动交易系统追求 Alpha 接受黑盒；投顾产品追求体验不担责；**观复=规则执行+人工确认+行为画像**——把吴老师 20 年书体系编码成可验证、可问责、可学习的执行器。三个架构推论都被正确执行：①信任边界明确（信号→确认→执行）；②可问责（每信号带理由+归因）；③可进化（信号注册制+Q11 参数学习化）。

## 二、架构评估（对照 spec 五层）

| 层 | 实现 | 架构判断 |
| --- | --- | --- |
| 数据层 | 7 免费源 API 链 + 降级 + 缺失机制分类 + SQLite 缓存 + 防前视边界 | ✅ MVP 数据层范本——三件套全有，大V 全 API 化（08-16） |
| 策略层 | 信号注册制 + B3 变体 + 打分制 + YAML 卖出规则 | ✅ 注册制是正确抽象——**单一策略依赖是最大结构风险** |
| 风险层 | 8 红线 + 仪表盘 + 归因 | ✅ 个人项目中少见 |
| 信号层 | gate_check + 在线评分 + 漂移检测 | ✅ 在线评分是亮点——多数系统做完回测就完，观复做了持续监测 |
| 确认层 | 半自动 + 理由 + 讲解 | ✅ 与"甲方是投资小白"完美匹配——兼任金融老师 |
| 推送层 | 晨报/周报/风险提醒 + 定时任务 | ✅ 可观测性完整——但定时任务两次翻车说明**调度层需要自检** |

**架构评分：8.3/10**（扣分：策略单点、调度自检缺失、归因粒度不足）

## 三、Agent 工程视角

**3.1 观复是"规则 Agent"而非"LLM Agent"**——确定性规则引擎+LLM 辅助讲解（LLM 只解释不决策）。MVP 阶段正确选择：确定性代码可回测/可单测/可问责。但"底座二期"（dsh 插件架构）方向对：Bull/Bear、四大师评审团必须在虚拟盘验证后接（红线已定）。

**3.2 记忆与上下文设计（Agent 系统的灵魂）**

- ✅ signal_ledger（策略记忆——不依赖 LLM 上下文）
- ✅ 行为画像 Q10（对"用户"的建模——多数 Agent 系统缺失）
- ✅ Q11 参数学习化（带版本可回滚）
- ⚠️ **知识库（三本书 29 万字）与运行时决策是"编译时"衔接**（人精读→编码规则）而非运行时检索——47 知识点只落了 B3/S2/S3 几条——阶段性正确，但二期必须有"剩余 40+ 知识点的落地通道"（否则书的价值只用 10%）

**3.3 观测性**
✅ 数据源状态段（缺口显式——UZI data_gap）/ ✅ 缺失机制分类（MNAR 诊断）/ ✅ 在线评分+漂移；⚠️ 定时任务自检缺失（两次翻车后才有 LastRun 验证习惯）

## 四、数据工程复盘

1. **防前视纪律**（08-16 修 8 处硬编码年份）——回测最常见的隐性污染——"数据边界=今天"显式锚定——90% 个人量化项目没有的自觉
2. **免费源降级链+缺失分类**——东财封锁处理教科书级：诊断（MNAR）→ 换源（同花顺）→ 标注（状态段）→ 备第三源（tushare）
3. **大V 数据 API 化**（08-16）——从"唯一浏览器依赖"到零浏览器依赖只花一天

- ⚠️ 批评：估值缓存积累良好但**无"数据新鲜度"监控**（源静默停更 3 天不报警）——二期加数据源健康检查

# 第三部分：风险与盲区（架构师 Q1-Q10 系统回答）

## A. 策略层风险（最重）

**A1 风格同质化——真风险。** 观复（估值面 30 分）+ 大V 主流（股息/低估值 60%+）同质于"红利风格"——2016-2025 是红利十年牛——**风格 Beta 贡献大部分收益的假设没有被证伪**。gate_check 的 Alpha>0 只测"组合 vs 沪深300"——**没测"组合 vs 红利指数"**。建议：虚拟盘判定加风格对照基准（红利低波）——Alpha 对红利指数不显著 = 风格暴露不是能力。

**A2 Alpha 来源未分层。** 组合 Alpha=择时（B3）+选股（打分）+仓位——只有一个聚合值。虚拟盘积累 ≥20 信号后做**信号类型归因**（淘汰负贡献信号）——决定"该加强什么"。

**A3 大V 假设验证通道。** 裁决：大V 假设（H1/H3/H4）**与书观点完全同权**——回测→（通过后）→虚拟盘验证。理由：大V 假设先验置信度低于书（幸存者偏差+组合≠实盘）——如果它直接进策略而书观点要虚拟盘，逻辑不一致。

## B. 执行层风险

**B1 8 万资金适配——被低估的约束。** 分散策略在 8 万+一手 100 股下不可执行（单只 10%=8000 元买不起茅台一手）。建议：策略注册表标注"最小资金需求"——候选策略必须 8 万可执行。

**B2 跟随粒度。** 超级鹿鼎公的"搬砖降本"（网格）比"买什么"更值钱——跟随仓 ≤20% 只约束标的没约束方法。Q13/Q18 抄底网格二期合并"网格降本"进增强仓——先回测。

**B3 S4 逻辑变化未信号化。** S1/S2/S3 都信号化了——**S4（逻辑变化）靠人发现**。建议二期：N8 大股东减持+财报暴雷检测自动监测（巨潮公告 API——a-stock-data 已有）。

## C. 数据/验证层

**C1 港股缺口。** 大V 1/3 是港股——港股通 50 万门槛（甲方 8 万不可执行）——**港股策略只进"观察池"（学逻辑）不进"操作池"**——边界确认即可。

**C2 大V 数据分级。** 48 组合里 9 个自认虚拟——`active_flag` 不可靠（小七停更仍 active）——组合加"实盘贴近度"（自述/停更时间/调仓频率三指标）——周报大V 段只显示高贴近度。

**C3 年化口径。** 总收益横比是陷阱——周报大V 段统一年化+风格标注。

**C4 实盘偏差对照。** 虚拟盘无滑点无手续费——真钱有冲击成本——真钱阶段起"虚拟盘 vs 实盘"逐周对照（偏差>2% 报警）——虚拟盘可信度最后闭环。

# 第四部分：方法论（资深 agent 工程师 × 投资经验）

### M1：验证纪律压倒开发冲动（观复最高方法论）

```
观点 → 回测（历史）→ 虚拟盘（实时前瞻）→ 真钱（小仓）→ 放大
每一层都有"不通过就停"的标准——从不让未经验证的东西接触真钱
```

Q6 教训（书观点未验证不落地）固化后体现价值——**系统的信任边界不是代码写的，是流程写的**。

### M2：信任边界分层（Agent 系统核心设计决策）

观复：**数据（全自动）→ 信号（规则+评分）→ 确认（人）→ 资金（人操作）**——越接近资金自动化越低。Agent 系统失败模式 90% 是"信任边界越界"（自动交易翻车/LLM 幻觉下单）。

### M3：可观测性 = 系统的自我辩护能力

每个决策要能回答三问：**当时看到了什么数据？基于什么规则？结果验证了什么？** 观复落地：信号账本+归因+在线评分+数据源状态段。**教训：静默失败比失败更危险**（定时任务两次翻车都是不可观测的静默失败——修复后加 LastRun 验证）。

### M4：文档即记忆（Agent 项目尤其重要）

观复 20+ 文档（技术方案/落地实施/待办/三本书审视/验收清单/运维教训）——对抗"会话丢失"的唯一武器——文档是外部记忆。验收清单解决"成功标准漂移"。

### M5：教训制度化（失败 → 规则 → 防再犯）

Go购 12 条 → 观复红线：**不记"这次别犯"，记"这类错误永远别犯"**——运维七章/记忆库 12+ 条教训。

### M6：最小可验证闭环（先跑通再优化）

MVP 路径每步可验证（M1/M2/M3 验收）——拒绝"全部弄好再说"（甲方多次批评文案堆积——正确）。

### M7：链路设计 = 信任边界设计（四问的方法论根）

不是数据流设计——是"每个环节把上一环的结论降级风险后传递"的设计。API 优先是架构决策：稳定>丰富；官方>爬虫；免费验证后付费。成功标准要"长在流程上"：标准+证据+状态+验收时间——否则就是纸面工程。

# 最后的话

观复最大的架构成就是**它把"投资人"和"工程师"两个角色用流程缝合了**：甲方拍板（决策权）、乙方执行（工程权）、数据裁决（中立权）——三方制衡。这正是架构师在复杂系统里追求的东西。

最大的架构风险不是代码——是**时间**：虚拟盘 4 周判定 vs 策略真实验证需要 1 年+。9/12 通过的只是"执行不走样"，不是"策略有效"。**甲方必须理解：通过判定 = 拿到真钱实验的入场券，不是策略成立的证明。** 这个预期管理，比任何代码都重要。
